# 專案使命與核心目標

## 專案定位

Frozen Rabbit's Cosmic（冷凍兔肉的宇宙）是 Final Fantasy XIV 宇宙探索高難度巧匠的 local-first 即時決策助手。玩家填入裝備、選擇配方，每一步回報實際技能結果與下一球色，系統再依完整 state 推薦下一技能。

它主要服務有滿等巧匠、願意依畫面逐步操作，希望學習高難製作或把即時計算交給工具的玩家。熟練玩家可以自行手工判斷；本產品的價值是把一般無球色求解器無法處理的當步機會轉成更高的完成與滿品質機率。

它不是固定巨集，也不承諾全域最佳。每一步以玩家實際回報的 state 重新規劃；初期產品先確保照建議操作的基本解題能力與讀球價值，玩家自行偏離後的深度救回在後續有足夠產品收益時再擴充。

## 求解器方向

使用者於 2026-09-05 重申：最終目標是做出手把手帶玩家完成高難配方製作的網頁。求解能力持續改善是產品主線，不能因為已有 UI 或採用基線就視為完成。

- 可以保留 Artisan fallback 並持續強化它，也可以在證據支持時建立自己的核心；混合架構可以是長期方案。
- 過往 Rust／TypeScript 研究與 Thiria 的可驗證能力都可以提供改善假說。舊實驗失敗只限制該實驗的結論，不永久封鎖整類方法；重開時說明新訊號、方法或成本條件有何不同。
- 是否值得採用，以完成成品、滿品質／有意義品質、重要情境與實際等待成本決定；不把「必須脫離 Artisan」、原創比例或架構新穎性當成產品 gate。
- 研究外部工具時先確認具體來源及可觀察能力，引用與實作依 [資料與證據規範](../domain/data_and_evidence.md) 處理。不把未知演算法寫成已整合能力。

這次方向更新解除先前對 fallback 替換與 Artisan 蒸餾的一概暫停；它不採用任何尚未驗證的候選，也不授權長跑。當前基線見 [current_state.md](../../current_state.md)。

## 核心使用流程

```text
填入裝備
  -> 選擇配方
  -> 取得下一技能
  -> 回報實際技能、成敗與下一球色
  -> 依新 state 重新推薦
```


常見路徑中，玩家照建議使用 100% 成功技能時主要只需點下一球；非必定成功技能仍需回報成功／失敗。自行選擇其他合法技能是正常操作，不是錯誤。

## 使用者價值

- 依實際面板與配方計算，而不是套用單一玩家 rotation。
- 利用高品質、高效、結實等當步機會，同時保留完工與回復路線。
- 產品只有一套預設策略（code 中仍稱 `Balanced`）：保住可退回的作業地板，並為玩家看得見的檔位與滿品質收益承擔可解釋的有限風險。先把這套策略做好，再由使用者另行決定是否重開其他取向。
- 比較完成與完成成品的品質收益。可依已揭露的證據接受值得的品質／完成交換，不把完成率字典序最大化寫成不可更改的規則；具體取捨見 [策略契約](../domain/solver_policy_and_safety.md)。
- Hard-quality 追求滿品質，一般收藏品顯示 100／300／700／滿品質四檔，HQ 類顯示 50%／75%／100% 語意檔位與隨品質上升的 HQ 機率；預設策略持續追求更高品質，不把 protected floor 當滿足點。
- HQ／Master 的滿品質尾端優先於未跨檔的小幅平均增益。
- 弱裝備仍提供誠實 best-effort，並說明可能交換的品質、完成或風險。
- 顯示推薦理由與替代技能的取捨，讓玩家保有最後決定。

## 正式支援情境

- 主戰範圍是有食物與藥、合理鑲嵌的 720／750 裝備；E02／E09 是主要非專家評測 profile。
- E03／E10 涵蓋專家，E05／E07 涵蓋不同合理鑲嵌強度。
- 未食藥、未鑲嵌或明顯不足裝備提供 best-effort，仍遵守合法性與誠實結果，但不以其滿品質率作主要產品 gate。
- 製作總步數會影響操作負擔，列為次要玩家量尺；overnight 總耗時屬研究迭代成本，仍影響下一輪是否值得投入。

## 產品底線

### 規則與決策分離

Mechanics engine 追求和遊戲一致，solver 只宣稱「依目前模型的建議」。Mechanics correctness、未來球色模型與策略效果使用不同 evidence，不用一個 confidence 掩蓋。

### 全配方整體發布

第一批產品範圍是 catalog 中全部 432 個宇宙探索高難度配方。相同求解規則的配方共用 family-level mechanics 與評測；發現遊戲實證反例後才建立例外。

最終是否發布由使用者自行驗收並決定。Agent 提供全 family 的成果、限制與失敗證據，不代替使用者判定可發布，也不另外要求先完成裝置清單、成功率門檻或備援架構才准許決策。產品不顯示配方成熟度分級；評測仍逐 family 揭露失敗。

### 求解器可靠性

主求解器沒有 policy-null 時，獨立快速求解器不是必要功能，也不列為首發門檻。若實際發現無建議問題，再依原因修正主求解器或評估後備方案，不預先要求雙求解器架構。時間、合法性與無建議契約由 [solver_policy_and_safety.md](../domain/solver_policy_and_safety.md) 擁有。

### Local、可恢復、尊重玩家

- 玩家實戰運算不依賴 server round-trip。
- Session 支援 undo、手動技能、resync 與主動 export。
- 不讀遊戲記憶體或封包、不自動按鍵、不做 bot。
- 目前交付平台是 Web，計算採 Rust→WASM；其他平台不是當前交付前提。

## 不在目前承諾範圍

- 跨多件製作的材料、分數、倒數與 Duty Action controller。
- 每個配方長期維護獨立 solver 或 recipe-ID patch。
- 無計算預算的搜尋；搜尋表示法與深度可依玩家收益和成本選擇。
- 用舊五配方逐手相容限制 generic solver。
- 以 synthetic、IID、fixed-tape 或 relaxed bound 宣稱真實成功率或理論上限。
- 讓舊 TypeScript solver 恢復演進。
- 未確認授權時複製第三方攻略、UI、圖示或 source implementation。

## 成功定義

- 已知 family 的新名稱配方可以 data-only 進入 catalog，不改 solver control flow。
- 提供全 catalog 的成果與限制，供使用者自行驗收及決定是否發布。
- 求解器接受玩家實際 action history；合法性、終局與必要品質不被破壞。
- 評測分開呈現 progress-only delivery、四檔／連續收藏品質量、hard-quality 滿品質、HQ 機率、裝備壓力與球色情境。
- 低裝備結果誠實，高裝備效果不外推成所有裝備保證。
- 玩家在目標裝置能低負擔回報並看懂下一技能與主要取捨。
