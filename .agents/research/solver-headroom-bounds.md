# 如何判斷求解器還值得改善多少

`last_reviewed: 2026-09-06`

## 問題與目前結論

使用者希望在 v2.2 後，先區分剩餘失敗是策略不足還是裝備／球色限制，避免為很少的改善耗費不成比例的時間、token 與長跑成本。本文件是研究提案，尚未建立 Rust v2.2 的最佳成功率上界，也不指定新 overnight。

可行目標是建立「已知做得到」與「任何合法策略最多做得到」之間的區間，讓研究能按剩餘空間排序與停止。完整精確求解可能比改善策略更昂貴，因此基準本身也必須有預算；算不緊時回報 unknown。

產品優先順序由 [使命](../skills/mission/project_mission.md) 擁有；驗證與宣稱邊界由 [algorithm_verification](../skills/domain/algorithm_verification.md) 擁有；未決問題是 [RQ-05](open_questions.md)。

## 先固定「最佳」的意思

每份界限都綁定 mechanics／action schema、配方 mechanics family、裝備與專家資源、objective、初始完整 state、剩餘 action budget，以及 condition transition model。未來動作不能知道尚未發生的球色或 RNG。

Hard-quality 的起點可定義為：在 80 actions 內滿進展、滿品質完工的最高機率。令 `V*(s,h)` 為從可觀測 state `s`、剩餘 `h` 次操作開始，所有合法逐步策略中最佳的成功機率：

~~~text
已滿品質完工：V* = 1
失敗或剩餘操作耗盡且未達標：V* = 0
其他：V*(s,h) = max over legal a of Σ P(s' | s,a) × V*(s',h−1)
~~~

每個操作都消耗 action budget，包括不推進工序的技能，避免以工序數遺漏循環。若模型非 Markov，需將影響下一步分布的可觀測歷史納入 state。品質以外目標另定 utility，不能拿「進展完成」替代 hard-quality 成功。步數與計算速度仍是品質後的取捨。

一份 bounds 證明只對它宣告的 model 成立。目前 balanced-iid、normal-heavy-iid 是壓力假設，不能外推成遊戲真實機率。單一固定球序也不能代表整體條件分布。

## 如何閱讀區間與歸因

理想結果是 `L ≤ v2.2 的真正 model 成功率 ≤ V* ≤ U`。其中 L 是現有合法策略的已驗證下界；若來自抽樣，必須用合適的信賴下界並標示信賴層級，不能把觀測平均當精確下界。U 是有效的最佳值上界；若上界也由抽樣估計，整段區間須處理兩側的聯合不確定性。

| 例子（純示意） | 合理結論 |
| --- | --- |
| 現有策略 L=90%，最佳 U=91.2% | 可改善空間至多 1.2 個百分點；已可討論是否值得繼續 |
| 現有策略 L=70%，最佳 U=98% | 界限太寬；不能說策略確實浪費 28 個百分點，也不能說裝備已到頂 |
| 從初始 state 證明 U=0 | 在宣告模型及操作上限下不可達 |
| 找到可實際逐步執行、獨立驗證優於 v2.2 的替代策略 | 已找到可改善的策略缺口；不必等全域最優證明 |

建議使用三類結論：有可驗證改善、已接近模型上限、尚無法判定。當 U−L 小於值得投入的幅度，便停止該格的尾端研究；例如 1 個百分點只作討論例子，不自行訂成使用者的接受門檻。

已做錯數步後的 state 無解，只能說「現在救不回來」；不能反推起始裝備無解。歸因要同時看起始 state，以及路線何時失去機會。單次失敗也可能發生在最佳策略下，不能把每次失敗都標成策略錯誤。

## 既有工具能提供什麼

- `tools/evaluate-generic-capability-bounds/` 已有忽略 CP、耐久、setup 等限制的樂觀 action-gain bound。放寬後仍不足能證明某種不可達；放寬後足夠只能回報 inconclusive，沒有給最佳成功率。
- `tools/evaluate-generic-pathwise-headroom/` 與 `packages/policy-lab/src/capabilityHeadroom.ts` 有 frozen TS fixed-tape 搜尋／分類。知道未來球序後找到更好的路線，可以定位可疑決策，但未必是玩家當時可判斷的選擇。
- 有寬度／時間限制的搜尋沒找到路線，不能證明不存在。找到的最好路線也不是最大值的上界；只有完整求最優或帶有效證明界限的搜尋才可用於上界。
- 這些是歷史工具與概念參考。新 adjudicator 必須接 Rust mechanics 與 v2.2 的真實策略，不能用 frozen TS 結果冒充現行最佳界限。

## 建議的最小研究路線

先做離線 Rust 分析器，與 Web 每步推薦分開；它可以為後續多版策略共用基準。離線分析器可使用明示的 assumed-world 機率計算該模型上界，但不能把 evaluator 私有權重傳入 v2.2，讓被評估策略得到原本不具備的資訊。

1. **便宜的不可達檢查。** 遷移並驗證樂觀資源界限：只能放寬真實限制，不能誤砍合法技能。利用精確小題對照證明放寬方向正確；所有非法放寬造成的「成功」都只算上界。
2. **短尾端的精確／區間動態規劃。** 從少量代表性失敗與成功對照開始，把短尾端完整展開、合併相同完整 state。未展開分支保留合法的 `[L,U]`，最簡單是 `[0,1]`；不能把 unknown 當失敗。保留所有合法 root actions 的上界，不能把未被 beam 選中的技能當不存在。
3. **只延伸有價值的邊界。** 按剩餘不確定性及可能影響排序往前算；完整保留被暫停分支的界限。先跑固定小預算，再給同一批題目一個較高預算，衡量 gap 縮小量／節點／wall time。若加預算沒有收緊就停止該方法，記錄瓶頸，不能讓上界研究變成另一個無限長跑。

精確概率或具方向保證的數值區間是證明的一部分；浮點誤差、memo key 缺欄位、技能合法性或 horizon 不一致都可能破壞上界。最優值只需完整環境 state；評估固定 v2.2 的下界還需納入它會讀取的 planner context。

首輪應涵蓋正常高成功率格、F19 的弱收益格及 F36／F46 的壓力格，避免只挑容易證明的尾端。尾端可達只回答該 state 的問題；若未把從起點到各尾端的概率與所有可選路線一起界定，不能加總成初始成功率上界。

Bounded RTDP 的文獻提供同時收緊上下界、集中探索不確定狀態的思路；原文是 stochastic shortest-path 問題，我們需另按有限 action horizon 的 Bellman recurrence 驗證，不能直接宣稱套用即有保證：[McMahan、Likhachev、Gordon, 2005](https://ai.dmi.unibas.ch/research/reading_group/mcmahan-et-al-icml2005.pdf)。

若前述仍太鬆，才評估「允許預知未來」的 information relaxation 上界，以及以 penalty 收緊它的方法：[Brown、Smith、Sun, 2010](https://pubsonline.informs.org/doi/10.1287/opre.1090.0796)。給額外資訊只能讓理論最優變好，但在預知世界裡跑一次 beam 所找到的值依然不是上界；必須證明其最優／上界，以及 penalty 的有效性。

預知未來的反事實比較須共享明確的底層隨機機制，正確處理不同技能抽取次數、強制球色與 no-step action。不能直接拿 v2.2 實際看到的球色列表餵給不同動作，當作所有策略共享的同一世界。

## 報表、重用與停止

每個 family × equipment × world 至少列：現有策略估計與不確定性、有效 U、gap、證明／unknown 狀態、起點或尾端範圍、主要未解分支、節點數與耗時、預算耗盡原因、完整 input／model identity。硬品質以外目標分表。

Mechanics、裝備、objective、world、horizon 與 state 相同時，對所有策略的上界和子問題證明可供後續版本重用；策略升版只需更新對應下界及比較。模型改動則重新核對，不靠相同 family 名稱沿用證明。

64 次中的 64 次成功，不是 100% 真實成功率，也未必足以證明低於 1 個百分點的剩餘空間。診斷集與獨立確認用途需分開；反覆看結果調參、依結果停止時，不能繼續套用未考慮選擇偏差的固定樣本信賴區間。必要時採固定檢視點或有效的 sequential bounds，並處理多格比較。

下一輪的第一個成果應是「能否以有限成本收緊幾個代表格的上下界」與可重播證據，而非立即承諾全配方精確最優或另啟一輪調參長跑。若基準依然昂貴／鬆散，保留 unknown，以已驗證的局部改善與明示預算做取捨。
