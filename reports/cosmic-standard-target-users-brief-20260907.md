# 普通球色策略的目標使用者與確認規劃

使用者於 2026-09-07 明確要求持續改善直到足以正式支援，重點為兩類：Raphael 全通常只差一點滿品質，希望利用球色補足；Raphael 已能滿品質，希望躲過黑球保住成果。完成進展不是滿品質成功。

## 本輪開發與確認界線

先用原始普通策略與描述性 `generic-craft-exp-cosmic-standard-search` 比較，沒有實際淨改善前不升數字版號。先固定三種 recipe shape 做開發，原始選擇為 36175、36188、37985；每個結果綁裝備、配方資料與來源。Raphael 使用 repository 固定 revision，只有搜尋完成的結果稱為 optimal；逾時且無路線不代表不能滿品質。

第一類以可重播 Raphael 路線在全通常達 90%–不足 100% 品質作 near-miss；尚未證明 optimal 時，只稱該預算找到的路線。第二類要求同一裝備確實存在全通常滿品質路線。

開發用 seed 0–31。策略固定後才使用 seed 10000 起的獨立確認；看過結果後若調整策略，該批改列開發，不再當保留集。球色世界先明示 Normal/Good/Excellent = 78/20/2 的合成權重，並由 mechanics 遵守固定轉移。另規劃以逐位置 Excellent→Poor 注入測試辨識黑球脆弱處；不能把此權重稱為遊戲機率。

目標是每個目標切片接近 100% 滿品質，先以 99% 作確認候選目標；樣本數與區間必須明示，不能靠小樣本零失敗就宣稱 99%。保留集至少檢查滿品質、完成、失敗、非法／policy-null、步數與單步延遲。若無法達標，保留具體反例，不以全體平均掩蓋。無球色機會的路線仍須保留作壓力案例，不能保證隨機製作必然成功。

本輪保持共用 Rust mechanics 與現有特殊球色策略；普通策略只讀當前可觀測 state，不能讀未來亂數或選取配方 ID 特例。最終是否發布仍由使用者決定；本輪目標是提供可信的採用判斷與失敗證據，不自行部署。

## 階段結案

使用者隨後指定「做到一階段先進行收尾，不論有沒有達成目標」。本輪停止調參，未執行保留集或逐位置黑球注入，也未完成與原始普通策略的固定配對比較；實際結果及未達標原因由 [階段報告](cosmic-standard-search-stage-20260907.md) 管理。本規劃不構成繼續運算指令。
